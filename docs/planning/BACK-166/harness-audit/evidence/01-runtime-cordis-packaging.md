## 2. Cordis
- What: vendored, source-copied fork of the upstream cordis framework (Shigma/cordiverse), rescoped to `@deepseek-ai/*` (SOURCE/DOC B vendor/README.md#L3, manifest table L7-L21). `@deepseek-ai/cordis` = upstream cordis 4.0.0-rc.12 at commit 01b39624. 12 core vendored packages + 5 `vendor/im/*` (Satori-derived IM adapters). All MIT, upstream LICENSE kept (SOURCE: every vendor/*/LICENSE is "MIT License, Copyright Shigma").
- It is a fork with local patches: P2 `cordis/src/fiber.ts` lifecycle hardening (reentrant disposal, effect rejection while UNLOADING), P1 HMR locale removal, P3 JSDoc, U1/U2 backports of upstream PRs #271/#354 (SOURCE B vendor/README.md#L59 and the Patch/Upstream sections). Must be re-synced by hand; drift risk (INFERENCE). Small doc drift: docs/rescope.md lists loader 1.0.0-rc.8 / include 1.1.1 while vendor/README says rc.9 / 1.2.0 (SOURCE both files).
- Declaration model (DOC B docs/cordis-primer.md#L7-L13): plugin = function or `Service` subclass with `inject` + `apply(ctx)`; context = service repository (`ctx.tools`, `ctx.llm`, `ctx.sessions`); typed events via declaration merging with dispatch modes emit/waterfall/parallel/serial/bail; registrations are reversible effects (`ctx.effect`, `ctx.on`). Composition is by YAML "profiles" and "bundles" with patch layers, mounted by the loader (DOC B docs/architecture.md, Profiles and bundles). `dsh --profile web --dump-config` prints the tree.
- Standalone vs coupled (SOURCE, by imports):
  - Standalone-ish (no `@deepseek-ai/cordis` import in code):
    - `dsh-util-values`: 0/2 files import cordis (assertNever, deepFreeze, snapshotJsonValue). Yet package.json still declares cordis as a peer (INFERENCE: manifest convention).
    - `packages/core/tools/src/json-schema.ts`: only imports `HarnessError` from dsh-llm and util-values (B .../json-schema.ts#L14-L15). Bounded JSON-Schema validator; also `schema.ts`.
    - `packages/core/session/src/validation.ts` and `repair.ts`: only `node:path`, dsh-brand, dsh-llm types, util-values (B .../validation.ts#L7-L13, repair.ts#L8-L12). Event validation + interrupted-tool-call repair are pure. Only `session/src/index.ts` L9 imports Cordis (1 of 12 files).
  - Tightly coupled:
    - `dsh-scope`: 2/2 files import cordis `Context`/`Fiber` (B packages/core/scope/src/index.ts#L8-L9). Docs call it "dependency-free" (B docs/subsystems/core.md#L20), which is not true at import level.
    - `ToolExecutionPipeline` + `ToolsService` take a cordis `Context` and `ScopeKey` (B pipeline.ts#L2-L4); `ToolsService extends Service`.
    - `typert/registry` and `typert/protocol`: Context/Service in service.ts and index.ts.
  - The packages are published as workspace packages with `workspace:*` peers on siblings (e.g. dsh-tools peers agent, llm, scope, session, system-prompt, user-approval: B packages/core/tools/package.json#L41-L47). Even "pure" files live in packages whose install graph pulls cordis + siblings. INFERENCE: reuse of pure logic is realistically COPY/ADAPT of a file, not an npm dependency.

## 7. Risks (INFERENCE unless noted)
1. Pre-stable (alpha/rc only), weekly documented breaking churn; a consumer chases a moving API (5k commits in ~3 weeks).
2. Huge surface: 451 packages, 36 workflows, lockstep versions; the "loop" is inseparable from Cordis + session/projection/persistence/system-prompt/tools.
3. Vendored-fork maintenance: Cordis 4.0.0-rc.12 forked with lifecycle patches (P2); drift from upstream.
4. Supply chain: 12 patched third-party deps (exceljs 806-line patch, pi-ai patch), `minimumReleaseAgeExclude` bypass list for fresh packages incl. claude-agent-sdk, codex, cua-driver; native binaries per platform; lifecycle scripts allow-listed for node-pty, koffi, esbuild (SOURCE B pnpm-workspace.yaml#L37-L60).
5. Self-declared unaudited; the product executes model-generated code, shells, plugins (SOURCE B SAFETY.md#L7-L9). Sandbox is "same-world" only (B packages/sandbox/README.md#L12). Wrong fit as an authorization/evidence boundary for Kawalys.
6. Heavy runtime requirements (Node >=24.22.3, pnpm 11, node-pty/koffi builds; Electron optional) vs a lean BFF.
7. Ownership mismatch: DSH owns session log, approval, tool policy; Kawalys must own evidence, authorization, decisions, outcomes in Postgres/Descope. DSH persistence is JSONL/SQLite behind its own `session-persistence` seam (adapter needed).

## Reuse verdict per component (INFERENCE)
- Agent loop / Cordis container / session stack: REFERENCE (event-sourced log, "model-visible means logged", waterfall hooks, step/turn boundaries); REJECT adopting the runtime. DEFER if a subprocess agent is wanted later via `dsh-sdk-client` (out-of-process, alpha).
- Tool pipeline design (schema validation, pre/post-execute guards, abort codes): ADAPT/REFERENCE; `json-schema.ts` and `schema.ts` are COPY candidates (MIT, small, import only llm errors + util-values; check `HarnessError` coupling).
- Session validation/repair (`validation.ts`, `repair.ts`): REFERENCE/ADAPT (interrupted tool-call repair pattern); data model is DSH-specific.
- Vendored Cordis: REJECT for a React+BFF product unless a plugin container is explicitly wanted; if so prefer upstream cordis over this fork.
- LLM adapter seam (`registerAdapter`): REFERENCE only.
- Sandbox (Landlock/Seatbelt/Windows ACL): REFERENCE; not a Kawalys security control.
