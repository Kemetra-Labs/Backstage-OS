## 2. Sandbox (packages/sandbox/*)

  - macOS Seatbelt: allow-default + `(deny file-write*)` with write allow-lists [DOC] B packages/sandbox/sandbox-local/README.md#L77-L83.
  - Windows: WRITE_RESTRICTED token + capability-SID allow ACE per workspace + private per-session temp dir/SID + Low integrity label; native FFI runner [DOC] B packages/sandbox/sandbox-windows-acl/README.md#L11 and sandbox-local README#L83; [SOURCE] B packages/sandbox/sandbox-windows-acl/src/index.ts#L20-L32: "writes are restricted; reads, network, and process visibility are NOT"; no console isolation. - NOT sandboxed: danger-full-access; archive worktree cleanup (unconfined git); native external agents: Codex subagent `permissionMode` default `never` (native sandbox) with explicit `dangerously-bypass-approvals-and-sandbox` [DOC] B packages/subagent/subagent-codex/README.md#L52; Claude Code subagent honours native settings, offers `bypassPermissions` [DOC] B packages/subagent/subagent-claude-code/README.md#L54, and its workspace diffs "stay out of the parent Session" (#L12); ACP subagent auto-answers child permission prompts allow|reject (default reject) [DOC] B packages/subagent/subagent-acp/README.md#L162. ## 3. Subprocess and cancellation
- Per-spawn "owner" used for both signalling and proof of quiescence [DOC] B packages/subprocess/subprocess-local/README.md#L84.
  - Windows: private runner creates a kill-on-close Job Object and assigns the target to it (target starts only after assignment); terminate = IPC message to runner; host exit = runner SIGKILL so the Job handle closes [SOURCE] B packages/subprocess/subprocess-local/src/windows-job.ts#L95-L127; B packages/subprocess/win32-process/src/process.ts#L345 (KILL_ON_JOB_CLOSE), #L509 (AssignProcessToJobObject), #L630 (TerminateJobObject). Uses koffi native FFI [SOURCE] B packages/subprocess/win32-process/package.json#L38. Exclusions: breakaway processes; a narrow create-to-assign window can leave a suspended target if the runner is killed externally [DOC] README#L151. Fallback if Job unavailable: `taskkill /PID <pid> /T /F` [SOURCE] B packages/subprocess/subprocess-local/src/spawn.ts#L109-L125.
  - Linux: transient user-systemd scope, final SIGKILL to the scope; scope emptiness proves quiescence; fallback = detached PGID kill [SOURCE] B packages/subprocess/subprocess-local/src/linux-scope.ts#L365; B spawn.ts#L479.
  - macOS: PGID fallback only; escaped descendants not guaranteed [DOC] README#L84, #L154.
- Escalation: SIGTERM then SIGKILL after `graceMs` [SOURCE] B packages/subprocess/subprocess-local/src/spawn.ts#L360-L376. `waitForExit()` rejects if the owner cannot prove its range empty (no false "clean") [DOC] README (What can go wrong).
- Timeouts: deadline(signal, ms) fuses caller abort with timeout; `timedOut` and `aborted` are mutually exclusive first-cause flags on ShellRunResult [SOURCE] B packages/shell/shell/src/types.ts#L146-L158; worktree commands default 5 min [DOC] worktree README; bash-sandbox base config timeoutMs 60000 [SOURCE] B packages/bundle/base/cordis.patch.yml#L259-L262. timeout-policy guard is cooperative: a tool ignoring abort can hold the caller [DOC] B packages/guard/timeout-policy/README.md#L10.
- AbortSignal path: `ctx.tools.execute` passes caller-owned `exec.signal` to every tool body; abort before body = ABORTED_BEFORE_DISPATCH, after = ABORTED; timeouts stay TOOL_TIMEOUT [SOURCE] B packages/core/tools/src/pipeline.ts#L356, #L413; B packages/core/tools/src/contracts.ts#L279-L282; [DOC] B packages/core/tools/README.md#L135. tool-bash on abort stops the job, awaits settlement, then throws AbortError [SOURCE] B packages/shell/tool-bash/src/index.ts#L355-L363.
- Truthfulness of cancel/unknown: good design. Durable `job/registered`/`job/settled` events; a missing settlement "remains incomplete", consumers "must not invent a finish timestamp"; `producerReported` is false for forced teardown and does not certify resource release [DOC] B docs/subsystems/jobs.md#L27. Subprocess `done` rejection "does not prove whether target execution began" [DOC] subprocess-local README (What can go wrong). forge mutation results are tri-state ok/failed/unknown [SOURCE] B packages/experimental/forge-github/src/mutation.ts#L14, #L32-L36. Worktree failure after allocation names retained artifacts [DOC] worktrees.md#L15.
- Gaps: unhandled SIGTERM/SIGINT/SIGHUP, SIGKILL, OOM, native crash, power loss "need an external supervisor" [DOC] B packages/subprocess/subprocess-local/README.md#L155 and #L64. Linux uninterruptible I/O can block disposal indefinitely [DOC] README Known Limitations. Completed spill files in OS tmp are never deleted [DOC] README (Known Limitations).

## 4. Permissions / approvals
- Two orthogonal knobs bundled into presets: sandbox mode x approval policy [DOC] B docs/subsystems/permission-presets.md#L5-L11.
- Approval seam: `ctx.approval.request` -> closed outcomes `allowed-once | rejected | cancelled | unavailable`; callers deny unless allowed-once; missing/throwing answerer = unavailable [DOC] B docs/subsystems/approval.md#L21. Per-session policy `ask` (default) or `never` (reject everything) [SOURCE] B packages/interaction/user-approval/src/index.ts#L172. Who approves: whichever answerer plugin is composed (Web UI, ACP bridge); the service itself never prompts [DOC] B packages/interaction/user-approval/README.md#L167.
- Limits: only one-shot grants, no allow-always, no remembered rules, no grant store; request carries no tool arguments; valid only inside an open turn; pending approvals process-local [DOC] B packages/interaction/user-approval/README.md#L164-L168. No persisted approval decisions beyond the audit pair.
- Audit trail: `approval/asked` and `approval/decided` appended to the Session log, paired by a fresh ApprovalRequestId; policy changes recorded as `approval/policy` events [SOURCE] B packages/interaction/user-approval/src/index.ts#L247-L260, #L118-L122. Escalation (`sandbox_permissions` wider mode with justification) goes through the same approval before execution [SOURCE] B packages/sandbox/sandbox/src/escalation.ts#L1-L20.
- Pipeline order: pre-execute waterfall (hooks, permission, sandbox) -> ask -> approval -> monotonic guards -> execute; denials skip the body [DOC] B docs/tool-execution-pipeline.md#L9-L62. The `guard` packages are NOT security guards: repeat-tool-reminder is advisory loop hygiene, timeout-policy is a cooperative time limit [DOC] B packages/guard/repeat-tool-reminder/README.md#L10.
- Defaults (base bundle): sandbox mode = env DSH_PERMISSION_MODE ?? 'workspace-write'; approval = 'never' only if that env is danger-full-access, else 'ask'; presets read-only+ask, workspace-write+ask, danger-full-access+never [SOURCE] B packages/bundle/base/cordis.patch.yml#L249-L286. The sandbox-policy package alone defaults to read-only [SOURCE] B packages/sandbox/sandbox-policy/src/index.ts#L97. Windows uses pwsh-sandbox; bash-sandbox is disabled there (same file #L259-L267).
- Permissive options: `danger-full-access` preset (no sandbox, asks auto-rejected, so no human gate at all; "never" does not mean safe); the env switch; Auto review (sets danger-full-access + ask) [DOC] permission-presets.md#L19-L21; subagent bypass modes (explicit only). Defaults are not yolo.

## 5. Jobs / schedule / workflow (duplicate-scheduler risk)
- jobs (`ctx.jobs`): in-process registry of long-running background processes (bash kind) with owner authorization; not a queue [DOC] B docs/subsystems/jobs.md#L5-L27.
- schedule (`ctx.schedule`): host-wide durable task store (JSON or SQLite), 7 timing kinds (after, at, every, daily, weekly, cron, rrule), in-process segmented timers; delivery = enqueue a message into a Session; not atomic ("a crash can duplicate delivery"), "no generic retry loop", receipt is not model completion [DOC] B packages/schedule/AGENTS.md and B docs/subsystems/schedule.md#L5. This IS a scheduler; it only fires agent prompts, not jobs/CI.
- workflow (`ctx.workflowEngine`): model-written JS orchestration script that spawns subagents, runs in a PTC VM under the Session's file policy; one engine per context; not a DAG/queue engine [DOC] B docs/subsystems/workflow.md#L5.
- webhook: "no queue, retry, deduplication, execution status, crash replay" [DOC] B docs/subsystems/webhook.md#L23; B packages/experimental/webhook/README.md#L71-L72.
- Net: no durable task queue or workflow DAG engine; only schedule (durable timers) and in-memory jobs.

## 6. auto-review and forge
- auto-review: before EACH native or PTC inner tool call the current agent's own provider/model assesses the pending action (effects classed low/medium/high); an allowed call executes with FULL host access, a denied one falls back to ask; experimental, "can allow unsafe actions", shipped switched off [DOC] B packages/experimental/auto-review/README.md#L10, #L47-L64. It reviews tool calls, not diffs. Only `source.kind:'user'` text authorizes; project files/tool results cannot. Headless `--permission-mode auto --approval-policy never` makes denials final (AUTO_REVIEW_DENIED / AUTO_REVIEW_FAILED) [DOC] #L47-L60. Tests: 24 unit + 1 e2e [SOURCE] packages/experimental/auto-review/tests. INFERENCE: same-model self-review is not independent verification, and allow removes the sandbox.
- forge (`ctx.forge`) + forge-github via the host's signed-in `gh`: reads PR state, checks, review decision, mergeability, threads, diff (compare API pinned to head SHA, `stale` when head moved), commits, activity; writes: review comments/reviews, resolve/unresolve threads, mark-ready (`gh pr ready`), merge (REST PUT .../merge with method + expected `sha`; never enables auto-merge, never joins queue, never deletes branch), setAutoMerge (GraphQL, expectedHeadOid) [DOC] B packages/experimental/forge-github/README.md#L51-L63; [SOURCE] B packages/experimental/forge-github/src/provider.ts#L290-L315. PR creation is NOT a provider API: `gh pr create` run by the agent's shell is detected and bound to the Session by forge-session [SOURCE] B packages/experimental/forge-github/src/commands.ts#L20-L24. Writes are never retried; outcomes ok/failed/unknown.
- webhook-github: one HTTP route, verifies `x-hub-signature-256` with a secret from the credential store, returns 202, dispatches to rules that create Sessions [SOURCE] B packages/experimental/webhook-github/src/handler.ts#L94-L103. No dedupe/queue/retry.

## 8. Security risks (for Kawalys)
1. Windows sandbox is write-only confinement: reads, network, process visibility open; always `partial`; extra writable roots ignored; workspace ACEs are standing (left after dispose) [DOC windows-acl README#L11, sandbox-local README#L83].
2. No network egress policy anywhere; env credential scrub is a name regex /KEY|PASSWORD|SECRET|TOKEN/i, other names pass through [SOURCE] B packages/subprocess/subprocess/src/index.ts#L54, #L73; [DOC] subprocess-local README#L156.
3. Linked-worktree git commit under workspace-write is unsupported on Windows (no grant).
4. Auto review (LLM) grants full access on allow; same model as the agent; prompt-injection mitigated only by prompt rules [DOC].
5. `danger-full-access` + `never` = no sandbox and no human gate.
6. Worktree archive cleanup runs unconfined git; ignored files lost; branches never deleted so refs accumulate.
7. forge-github rides the host `gh` login (whatever scopes) and can merge PRs; head-SHA pinning is a good guard. `gh api`/`gh pr create` run by the agent shell are observed, not gated, by forge-session.
8. Injection surface: worktree/forge use literal argv, no shell (good); bash/pwsh tools are arbitrary shell by design, gated only by sandbox/approval. Windows runner needs koffi native code (probed per spawn).
9. Process cleanup guarantees stop at JS-observable exits; SIGKILL/crash need an external supervisor; macOS descendants can escape.
10. Native subagent (Claude Code/Codex) diffs are invisible to the parent Session [DOC subagent-claude-code README#L12]: the "agent self-report is not evidence" problem; independent verification must come from git/CI.

## Reuse verdict for Kawalys (INFERENCE)
- ADAPT/REFERENCE: worktree pinned-commit create + conservative remove + restore; tri-state mutation results; truthful job/settlement semantics (missing settle = incomplete); approval audit pair + closed outcome enum; head-SHA-pinned forge writes; Windows Job Object kill-on-close pattern.
- DO NOT adopt as a control: Auto review, Windows sandbox as isolation boundary (write-only), schedule (would duplicate a scheduler; at-least-once with crash duplicates), one-shot-only approvals (no persistence/grant store).
- Everything is cordis-service-coupled; extraction means copying files, not importing packages. docs/subsystems/scope.md is about scoped registration/lifetime, not isolation.
