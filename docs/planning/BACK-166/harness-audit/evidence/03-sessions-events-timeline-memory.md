## 1. Session / event model
- Envelope (SOURCE packages/core/session/src/types.ts#L518-L541): {type, seq, time(ms), data, ignorable?} plus surfaceOp/sourceEventSeqs only on surface events. Branded SessionSeq = non-negative safe int, contiguous per session (#L33-L45; DOC docs/subsystems/session.md#L841).
- No event id, no parent/causal id, no hash chain. Causality is by seq references (sourceEventSeqs, surfaceOp.replace startSeq/endSeq, headerSeq), turn/step numbers, and callId pairing tool/call with tool/result (#L381, #L395). INFERENCE: dedupe key = session id + seq (DOC docs/subsystems/session-telemetry.md says receivers dedupe on session.id, format_version, event.seq).
- Core union SessionEventMap (#L302-L448): turn/start, turn/end, step/start, step/end, user/message, developer/message, system/message, assistant/message (embeds raw timed stream + usage), assistant/attempt, tool/call, tool/result (error, opaque JSON meta), request/header, request/context, session/end-seed. It is merge-extensible: ~63 repo-declared types (SOURCE packages/core/session/src/known-event-types.ts#L22-L88), incl. approval/asked|decided|policy, compaction/*, subagent/catalog|descriptor, job/registered|settled, hook/invoked|result, workspace/changes, tool-workflow/*, team/*, todo/write, goal/change, llm/retry, model/selection, command/run|done, feedback/*. Generated catalog: docs/persistence-catalog.md (DOC, 388 KB). Experimental plugin:* records are in a separate catalog (DOC docs/experimental-persistence-catalog.md#L16-L33).
- Header is a separate first line, not an event: version, id, createdAt, cwd, parentSession, isSeeded, origin(subagent|side), delegationDepth, agentPreset (SOURCE types.ts#L95-L141).
- Storage: JSONL per session, default zstd "checksummed frames" (zstd frame checksum, not a chain hash), or raw JSONL with compression:'none' (DOC packages/session/session-persistence-jsonl/README.md#L12, #L48). Filename session.vN.jsonl[.zstd] (SOURCE packages/session/session-format/src/filename.ts#L8-L22). Optional SQLite backend, one row per event plus derived tables for model calls, tool calls, compactions (DOC docs/subsystems/persistence.md#L358). Fixture shape: header line then {"type","data","surfaceOp","seq","time"} rows (SOURCE packages/experimental/webworker-runtime/tests/fixtures/vfs-example/home/sessions/--dsh-workspace--/preview-architecture-review/session.v3.jsonl#L1-L6). That fixture is v3; the current writer is v4.
- Versioning: single integer SESSION_FORMAT_VERSION = 4 (SOURCE types.ts#L90). Immutable per-generation files, adjacent migrations v0->v1->v2->v3->v4 as packages (packages/session/session-format-v*-to-v*). Old versions migrate in memory on read; a write open publishes a new generation (DOC persistence.md "Format refusal"). Unknown event types without ignorable:true make a reader refuse (SOURCE types.ts#L526-L536).
- Mutability: append-only, committed events never rewritten (DOC persistence.md "SessionHandle"; SOURCE types.ts#L296-L301). Exceptions: torn-tail repair, and crash-orphaned turns get a synthetic turn/end{interrupted} on resume (types.ts#L242). Single-writer lease. Append is buffered; durable only after flush (DOC persistence.md "The flush checkpoint").
- Integrity: no per-event hash or signature. Only zstd frame checksums and seq contiguity validation (validateSessionLog, exported at packages/core/session/src/index.ts#L42).

## 2. Coverage vs Kawalys needs
- Tool calls, args, results: YES. Raw arguments string; tool/result message, structured error{name,code,reason}, JSON meta incl. fs contextual diff (types.ts#L381-L405).
- Approvals: YES, log-only audit: approval/asked(id,toolName,callId,reason), approval/decided(outcome allowed-once|rejected|cancelled|unavailable), approval/policy, permission/preset (SOURCE docs/persistence-catalog.md#L226-L292; packages/interaction/user-approval/src/types.ts#L32). No approver identity in these payloads (INFERENCE). A later change record "user-rpc-principal" exists (docs/persistence-changes/2026-10-13-user-rpc-principal.md); I did not inspect it.
- Cancellation: YES. turn/end{aborted, reason user|parent|hook|disposed|legacy} (types.ts#L209-L224); interrupted assistant prefix flagged interrupted:true (#L368); unfinished tool calls get TOOL_NOT_STARTED / TOOL_OUTCOME_UNKNOWN (SOURCE packages/core/session/src/repair.ts#L15-L18).
- Errors: YES. turn/end{error: LlmFailure}, tool error, llm/retry events.
- Token usage: YES per assistant message: input, output, total?, cacheRead/Write, reasoning (types.ts#L367; packages/llm/llm/src/types.ts#L182). Money cost: NO (tokens only; DOC packages/llm/token-meter/README.md#L12).
- Subagent/child runs: PARTIAL. Child is its own session with header parentSession, origin 'subagent', delegationDepth. Parent logs subagent/catalog{childId, childCreatedAt, name, mode, label}; child logs subagent/descriptor (SOURCE packages/subagent/subagent/src/catalog.ts#L26-L38; descriptor.ts#L33-L40). I found no explicit parent callId in the catalog event (INFERENCE, not exhaustive). Export bundles children (DOC packages/session-query/session-log-export/README.md#L10). job/registered carries optional creating toolCall (SOURCE packages/jobs/jobs/src/types.ts#L24-L36).
- File diffs/worktree: MOSTLY NO in the log. workspace/changes is only {turn}; summary and diffs stay on the Host and are served only while the Session lives (SOURCE packages/deliverables/workspace-changes/src/types.ts#L106-L116). Per-file diffs ride in fs tool result meta. Worktree facts are experimental records plugin:worktree/created|entered.
- Missing for Kawalys: evidence citation/source ids, actor identity, tamper evidence, money cost, durable diffs, cross-session stable ids (only per-session seq).

## 3. Timeline and projections
- packages/experimental/timeline is NOT an event-log timeline/replay viewer. It is an agent task-tree, progress and timed interval-report plugin using plugin:timeline/* records (DOC packages/experimental/timeline/README.md#L8-L12; records at docs/experimental-persistence-catalog.md#L22-L33). Not reusable for Flight Deck/Replay.
- session-inspector is a virtualized raw-log and chat-group table UI inside the DSH web client (DOC packages/experimental/session-inspector/README.md#L8-L12). DSH-specific UI (INFERENCE).
- Projections (DOC docs/subsystems/session-projection.md#L5; interface at #L48-L120): ProjectionDefinition{key, stateSchema(zod), init(header, inheritedCount), apply(state,event)->state, wire.view, stateVersion}. apply is a pure synchronous fold, state is plain JSON, checkpoint plus tail replay equals full replay, snapshots carry asOfSeq. This is a good pattern for a Replay view. The registry is a Cordis service over a Session (packages/session/session-projection/package.json: peerDeps cordis + dsh-session, dep zod).
- Pure helpers in core: foldSurface, deriveEventMessage, foldRequestHeader, validateSessionLog (SOURCE packages/core/session/src/index.ts#L38-L42). session-query classifies events current/shadowed/log-only with the same fold (DOC docs/subsystems/session-query.md#L12).

## 4. Can an external app read DSH sessions?
- Technically yes. Plain JSONL (or zstd of it); machine-generated schema docs/persistence-schema.json (233 KB; digested roots for header, JSONL header line, envelope, every event; SOURCE docs/persistence-schema.json#L1-L7), per-change records and per-format schemas under docs/persistence-changes/ (historical-formats v0..v4).
- Stability: strict, compatibility-reviewed process (DOC docs/session-format-status.md#L32 finalized v4; #L45-L46 released v4, evidenceTag dsh-v0.2.0-rc.2). Alpha/rc publication still carries released-format obligations (status doc "Sources of truth"). Caveats: product is 0.2.x alpha; additive changes continue under the same version number ("Schema changes may remain V4"); plugin record payloads are owner-validated unknown JSON (types.ts#L549-L574); default on-disk is zstd so a reader needs a zstd decoder or compression:'none' (jsonl README#L48); a strict reader must refuse unknown non-ignorable event types.
- A read-only importer pinned to v4 for turn/step/tool/approval/usage/subagent/compaction events is feasible (INFERENCE).

## 5. Memory / compaction / context vs K.Brain
- No long-term memory subsystem. The only hit is Ralph's note that the workspace is the sole cross-round memory (DOC packages/experimental/tool-ralph/README.md#L163). No memory tool in docs/tool-catalog.md.
- Context: AGENTS.md/CLAUDE.md chain loader with byte budget (DOC packages/context/agent-instructions/README.md#L10-L12); file-reference, session-reference, time/tmux context. Experimental session search tools over earlier sessions, off by default, authorized by exact cwd match (DOC packages/experimental/tool-session-query/README.md#L10-L12; session-search README#L10-L12).
- Compaction: lock-bracketed compaction/start|summary|end; summary appended as user/message with surfaceOp.replace; shadowed seqs, token counts, summarizer provider/model/usage logged; model-free compaction/prune; image offload (SOURCE docs/persistence-catalog.md#L383-L492; DOC docs/subsystems/compaction.md#L7-L20). The raw log is never discarded; compaction changes only the model-visible surface.
- Overlap with K.Brain: none functionally. DSH has no evidence citations, provenance model, or authorization on knowledge items. Only reusable idea: "shadowed seqs + replace op" as a provenance pattern for derived summaries (INFERENCE). K.Brain stays BUILD.

## 6. OTel / telemetry
- ctx.otel is a factory; mounting alone allocates no transport (DOC docs/subsystems/otel.md#L7-L9).
- Session-log feedback telemetry: default mode FEEDBACK_ONLY, records leave only after explicit user feedback; DISABLED builds no transport; exporter URL required (DOC packages/session/session-telemetry-otel/README.md#L14, #L36-L37).
- Product analytics: DESKTOP phones home by default. enabled defaults true, no user-facing control; Web does not (DOC packages/client/product-analytics/README.md#L10, #L24). Default endpoint https://dsh-otel-collector.deepseeksvc.com/v1/logs (DOC packages/host/product-telemetry-otel/README.md#L34, #L43). Carries device_id, user_id, app_version, OS/CPU fields; excludes keys, prompts, responses, hostnames. Override: DSH_PRODUCT_ANALYTICS_OTLP_URL.
- session-log-deepseek is mounted in shipped profiles and adds a dsh_session_log field to requests to the OFFICIAL DeepSeek API by default; enabled:false stops it (DOC packages/session/session-log-deepseek/README.md#L10, #L35). Matters if Kawalys embeds DSH profiles.
- Export is OTel log records, not spans/metrics (INFERENCE from the docs above).

## 8. Coupling
- packages/core/session/src/types.ts imports only dsh-brand, dsh-llm types, typert-protocol types, util-values (SOURCE #L1-L18). surface.ts and known-event-types.ts are cordis-free. The package entry index.ts imports @deepseek-ai/cordis (#L9), but package.json exports subpaths ./types, ./surface, ./fork. So the schema and fold are usable without the Cordis runtime via subpaths (still needs dsh-llm, dsh-brand, dsh-util-values; whether those are published to npm is unverified).
- session-format: peerDep cordis. session-projection: peerDeps cordis + dsh-session, dep zod. session-query: deps session-format-catalog + zod. persistence-jsonl: native addons (koffi, node-addon-system), heavy.
- Cheapest reuse: ADAPT the envelope plus a read-only JSONL reader plus a pure fold; REFERENCE the rest. Do not take the runtime.

## Bottom line
1. DSH events are a ready REFERENCE for Flight Deck/Replay vocabulary (turn/step/tool/approval/usage/subagent/cancel) and for the checkpointed pure-fold projection pattern (ADAPT the pattern).
2. Do not adopt DSH as a second event store: no evidence ids, actor identity, hashes, durable diffs, or cost. Kawalys evidence stays canonical. If DSH-run sessions must show in Flight Deck, build a one-way importer from pinned v4 JSONL into Kawalys' evidence model.
3. The timeline package is unrelated to replay. Nothing to reuse for K.Brain.
4. Privacy: Desktop default-on product analytics and official-API session-log upload exist; disable explicitly in any DSH deployment.
