# Brain slice 1: BACK-154 and BACK-155 cleanup — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:executing-plans (native) for this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** close the remaining BACK-154 and BACK-155 engineering items with tests and measured evidence. The work stays local and stops for owner approval before any commit.

**Architecture:** two small code changes in the pure cognitive modules and the cognition route:
- `readLesson` refuses a malformed `now`;
- the validator gets a serialized entry point with a byte cap.

One small runtime guard limits how many cognition reads run at once. Everything else is measurement scripts (named `*.measure.ts`, so they are never CI gates), test pins of existing privacy properties, and recorded decisions. No schema, dependency or route change.

**Tech stack:** NestJS, node-postgres, Jest 30 (run through `npm test`, which needs `--experimental-vm-modules`), testcontainers PostgreSQL 18.

**Spec:**
- [BACK-154](https://rahmaqanater.atlassian.net/browse/BACK-154) (COG-09) and [BACK-155](https://rahmaqanater.atlassian.net/browse/BACK-155) (COG-10);
- the owner's roadmap message of 2026-11-28, slice 1;
- `docs/planning/BACK-111/cog-08-acceptance-matrix.md` sections 20 to 22.

## Global Constraints

- No commit, push, PR, merge or deploy without the owner's approval. The work ends with one approval request.
- No new dependency, schema, migration, route, provider or LLM.
- Reuse first: the `MemoryRepository` budget (#179), `SignInRateLimiter`, the safe-error filter, the `memory.measure.ts` harness, and the BACK-172 (#178) primitives.
- Unknown is never Healthy. Over budget or at capacity, a read fails closed with the generic error body, never with a partial answer.
- A timing result is never claimed as equality. Any residual is *proposed* for the owner's decision (BACK-155 Q1).
- Measurements run at an exact SHA and are recorded with it, along with what was NOT RUN.

## Review Focus

1. **Concurrent reads at the cap:** the next read gets the generic error at once, without queueing or waiting on the pool. A slot is always released, also when the read throws.
2. **A hidden project under load:** it takes a slot exactly as a visible project does. The cap is checked before the read, for every valid UUID, so being at capacity reveals nothing about whether a project exists.
3. **A candidate just over the byte cap:** it is refused without `JSON.parse`. A legitimate result of maximum size (50 tasks × 20 requirements, 100-char ids) is accepted.
4. **`readLesson` with an empty history and a bad `now`:** it throws, as it does with rows.
5. **The live search URL:** no server log line or proxy access log carries `q`.

### Task 2: the validator's serialized boundary (BACK-155 AC3, Q2)

**Files:**
- Modify: `server/src/reasoning/reasoning.validator.ts`
- Test: `server/test/reasoning/reasoning.limits.spec.ts` (new)

**Interfaces:**
- `export const MAX_CANDIDATE_BYTES: number`
- `export function validateSerializedResult(projection: MemoryProjection, input: ReasoningInput, json: string): boolean`. It returns `false` when `typeof json !== 'string'` or `json.length > MAX_CANDIDATE_BYTES`, without parsing. Otherwise it returns `validateResult(projection, input, JSON.parse(json))`, and `false` on a parse error.

How to set the cap: build the largest valid input the rules allow (`MAX_TASKS` tasks × `MAX_REQUIREMENTS` requirements, ids of `MAX_ID` characters, longest refs). Serialize the evaluator's result for it. Set `MAX_CANDIDATE_BYTES` to the next power of two at or above twice that length, and record the measured length in the test.

- [ ] Test `'the largest legitimate result fits the cap'`: its serialized result's length is ≤ `MAX_CANDIDATE_BYTES`, and `validateSerializedResult` accepts it.
- [ ] Test `'one byte over the cap is refused without parsing'`:
  - spy on `JSON.parse`;
  - pass a string of length `MAX_CANDIDATE_BYTES + 1`;
  - expect `false` and zero calls.
- [ ] Test `'malformed JSON and non-strings are refused'`.
- [ ] Run. Expected: FAIL (the symbol is missing). Implement. Run `npm test -- test/reasoning`. Expected: all pass, and the reasoning guard spec still passes.
- [ ] Record the Q2 answer in the matrix: the first reliable boundary is the serialized string, at any future transport (BACK-156, BACK-168). In-process candidates come from our own evaluator.

### Task 3: a cap on cognition reads in flight (BACK-154 bounded concurrency)

- Create: `server/src/cognition/read-slots.ts`

**Interfaces:**
- `export class ReadSlots { constructor(max: number); tryAcquire(): boolean; release(): void; readonly inFlight: number }`
- `export const COGNITION_READS_IN_FLIGHT = 4`, below the app pool's `max` of 10, so cognition can never take every connection.
- In the controller, after the query and UUID checks and immediately before `readVisible`: if `!slots.tryAcquire()`, throw `HttpException('', 503)`, which the filter maps to the generic `internal_error`. Then run the read in `try { … } finally { slots.release() }`.

- [ ] Unit tests:
  - `tryAcquire` is true up to `max` and false after it;
  - `release` frees a slot;
  - `release` never drops below 0;
  - the constructor refuses a `max` that is not a positive integer.
- [ ] Controller test `'at capacity the read is refused at once and never reaches the repository; a throwing read releases its slot'`.
- [ ] Run (FAIL), implement, run `npm test -- test/cognition`. Expected: all pass, and the guard spec passes with the new import allowed.
