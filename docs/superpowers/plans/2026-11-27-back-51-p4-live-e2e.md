# BACK-51 P4: live end-to-end suite and CI job — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One Playwright suite that runs the whole gate path (sign in → Portfolio → Investigation → record a decision → see it → sign out) against the real BFF on a disposable Postgres, plus its negative cases, wired into CI as one job.

**Architecture:** A test-only server entry under `server/test/e2e/` builds the real `createApp` with the existing `FakeIdentityVerifier` on a Testcontainers Postgres, seeded with `seedLocal()`. A new Playwright config in `app/` starts that server and a live-mode (`VITE_KAWALYS_LIVE=1`) `vite preview` whose `/api` proxy already points at `127.0.0.1:8787`. The browser signs in by POSTing the fake owner token to `/api/auth/session` from inside the page, so the real `__Host-` cookie path is used. CI gets one new job selected by a new classifier flag.

**Tech Stack:** NestJS 12 BFF, `@testcontainers/postgresql`, TypeScript, Vite 5, `@playwright/test` 1.65.1 (Chromium only), bash classifier, GitHub Actions.

**Spec:** [docs/planning/BACK-51/gate-path-plan.md](../../planning/BACK-51/gate-path-plan.md) section 3 "P4" and section 4. Read it first.

## Global Constraints

- No new dependency in `server/` or `app/` (CLAUDE.md "Reuse before build" does not authorize them). Use what is already installed.
- The e2e server entry and anything that selects `FakeIdentityVerifier` live under `server/test/` only, never under `server/src/`.
- Loopback only: the e2e server listens on `127.0.0.1:8787`; it refuses `NODE_ENV=production`.
- The default app build and the existing `app/e2e` suites stay byte-for-byte unchanged in behaviour. Live build output goes to `app/dist-live/` (gitignored), never `app/dist/`.
- Chromium only for the live suite (gate-path-plan §5: WebKit `__Host-`/`Secure` cookies over http are unverified).
- `workers: 1` (repo CLAUDE.md: parallel workers gave false timeouts on Windows).
- Every new user-visible string needs EN and AR. (This plan adds no UI strings; tests assert the existing AR copy.)
- Never add `paths`/`paths-ignore` to `ci.yml`; the required check name `Playwright (chromium + webkit)` on the `gate` job stays. Classifier and its test change together.
- **No `git commit`, push or PR.** CLAUDE.md requires explicit owner approval; the owner has not given it. Leave changes in the working tree.
- Docker must be running locally for Tasks 1–3 (Testcontainers). No skip switch.

## Review Focus

1. **Session ends while a decision is typed** → draft survives, re-sign-in, exactly one decision recorded. (Task 3 test `session expiring mid-form keeps the draft`.)
2. **Double click on submit** → one decision, proven by the server list count, not the UI. (Task 3 `double click records one decision`.)
3. **Hidden vs missing case** → another workspace's investigation id and a random UUID give the same 404 `not_found` body; the foreign project name never reaches the page. (Task 3 `another workspace sees nothing`.)
4. **Sign-in rate limit trips mid-suite** (10/min default) → the suite would fail for the wrong reason. The e2e server sets `KAWALYS_AUTH_SIGN_IN_LIMIT_PER_MINUTE=100`. (Task 1 env test.)
5. **Tests that depend on absolute counts break on re-runs or ordering** → every decision assertion counts the delta from a read taken in the same test. (Tasks 2–3.)
