# BACK-33: SonarCloud S6845 on the pilot tables (keyboard evidence and hand-off)

Rule `typescript:S6845` ("Non-interactive elements should not be assigned mouse or keyboard event handlers / tabIndex") flags `tabIndex={0}` on the three `role="region"` scroll wrappers in `app/src/design-lab/v2/bc/Tables.tsx`. Nothing was accepted, suppressed or marked `NOSONAR` in this change. The owner decides each warning in SonarCloud; this page is the evidence.

Live issue IDs: BLOCKED: live issue IDs not retrievable without a SonarCloud login. No project key is discoverable in the repo (`.sonarcloud.properties` has none; analysis is automatic), so no API request was made. Line numbers below come from the source.

Why the tab stop exists: a scrollable container that cannot take focus cannot be scrolled from the keyboard (WCAG 2.1.1). Tab stops on the wrappers are the only way to reach overflowing table content without a mouse.

## Evidence

Test: `app/e2e-v2/bc.spec.ts`, "list tables: each scroll region is reachable by Tab, named, and scrolls with the arrow keys" (describe `phone`). For each region, EN and AR, list view, it focuses the last tabbable control before the region, presses Tab once, and asserts `document.activeElement` is the region. It asserts `role=region` and the accessible name. If `scrollWidth > clientWidth` it presses ArrowRight (EN) or ArrowLeft (AR) and asserts `scrollLeft` changes. It tries 375 px first and 320 px only if 375 does not overflow. Chromium only. Synthetic demo data.

An extra one-off probe (not in the suite) read all three wrappers at 480, 640, 641, 768, 900, 1024, 1280 and 1440 px in EN and AR: none overflowed at any of them. At phone widths the matrix and links tables stack to one card per row, so on current demo data these two wrappers are focus stops with nothing to scroll. That is a real finding, not a keyboard failure: the tab stop is announced as a named region but is inert. Content that overflows (longer real labels, 200% text zoom) was not tested. The suitable fix is to make `tabIndex` conditional on overflow, or drop it where the table cannot scroll; that is product code and is out of scope here.
