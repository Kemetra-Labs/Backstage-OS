# BACK-33: SonarCloud S6845 on the pilot tables (keyboard evidence and hand-off)

Rule `typescript:S6845` ("Non-interactive elements should not have tabIndex", the jsx-a11y `no-noninteractive-tabindex` check) flags `tabIndex={0}` on the three `role="region"` scroll wrappers in `app/src/design-lab/v2/bc/Tables.tsx`. Nothing was accepted, suppressed or marked `NOSONAR` in this change. The owner decides each warning in SonarCloud; this page is the evidence.

Live issue IDs: BLOCKED: live issue IDs not retrievable without a SonarCloud login. No project key is discoverable in the repo (`.sonarcloud.properties` has none; analysis is automatic), so no API request was made. Line numbers below come from the source.

Why the tab stop exists: a scrollable container that cannot take focus cannot be scrolled from the keyboard (WCAG 2.1.1). The wrapper's tab stop is the mechanism that makes overflowing table content reachable without a mouse.

## Evidence

> Update (BACK-92 R4): `app/e2e-v2/` retired. The same checks for the three map tables now run in `app/e2e/scroll-regions.spec.ts` (the `map systems ledger`, `map source readings` and `map links` regions at 200% text, and the ledger at default size at 320 px), on the host route `#/map`. The text below describes the original lab test.

Test: `app/e2e-v2/bc.spec.ts`, "list tables: each scroll region is reachable by Tab, named, and scrolls with the arrow keys" (describe `phone`). For each region, EN and AR, list view, it focuses the last tabbable control before the region, presses Tab once and asserts `document.activeElement` is the region. It asserts `role=region` and the accessible name. If `scrollWidth > clientWidth` it presses ArrowRight (EN) or ArrowLeft (AR) and asserts `scrollLeft` changes. Chromium only. Synthetic demo data. Two scenarios, both asserted:

- Default size: 375 px, then 320 px if 375 does not overflow. The test fails unless the ledger scrolls by arrow key at 320 in EN and AR.
- 200% text-only resize (WCAG 1.4.4), approximated by doubling the px font tokens (`--kv2-t-*`) and the `.kv2-table` font sizes. The test fails unless each table overflows (at the width listed) and scrolls by arrow key in EN and AR. This is an approximation, not a browser text-zoom setting.

| Tables.tsx line | Region name EN / AR | Overflow at default size (scrollWidth / clientWidth) | Overflow at 200% text | Reached by Tab | Scrolled by arrow key | Recommended disposition |
|---|---|---|---|---|---|---|
| 31 | Systems ledger / سجل الأنظمة | 375: none (349/349). 320: yes, EN 349/294, AR 333/294 | 320: EN 598/294, AR 473/294 | yes, EN and AR | yes, both scenarios, EN and AR | Accept |
| 79 | Source readings / قراءات المصادر | 320 and 375: none (294/294, 349/349); none up to 1440 in a one-off probe | 641: EN 769/615, AR 641/615 | yes, EN and AR | default: n.a. (nothing to scroll); 200% text: yes, EN and AR | Accept |
| 111 | Links between systems / الروابط بين الأنظمة | 320 and 375: none (294/294, 349/349); none up to 1440 in a one-off probe | 320: EN and AR 385/294 | yes, EN and AR | default: n.a. (nothing to scroll); 200% text: yes, EN and AR | Accept |

Reading: at default size the matrix and links tables stack as cards on a phone and fit at every width, so their wrappers do not scroll. For low-vision users resizing text to 200% they do overflow, and the tab stop is then the only way to scroll them from the keyboard. Removing `tabIndex` from either would be a WCAG 2.1.1 failure. A conditional `tabIndex` (only while overflowing) would also satisfy 2.1.1, but only if it is re-evaluated on resize and font change (for example with a `ResizeObserver`); never remove it outright. That is a product change and out of scope here. Other cases (text spacing, 1.4.12) were not all tested: a reviewer probe found the ledger also overflows at 375 px with text spacing applied.
